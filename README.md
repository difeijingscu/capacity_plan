# 算力沙盘（Capacity Sandbox）

> 推演算力空间，洞见投资回报。

单用户、本机运行的算力沙盘网页应用。支持业务场景、创新服务、开发测试三个独立资源池，采用固定公式和可追溯参数进行早期估算。

项目最新结构、模块状态、计算口径、改动入口与已知问题见 [项目架构](./项目架构.md)。后续开发先读该文件，并在相关变更时同步更新；协作规则见 [AGENTS.md](./AGENTS.md)。

## 启动

迁移到另一台Windows机器，请优先阅读根目录的《部署.md》或同名《部署.html》。Windows运行包内置Python运行环境和已构建网页，完整解压后双击启动.bat即可，无需安装Python、Node.js或Git。检查环境.bat与停止.bat分别用于诊断和退出。

当前工作区的依赖与网页构建已准备完成。双击根目录的 **启动.bat**，浏览器将打开：

[http://127.0.0.1:8000](http://127.0.0.1:8000)

也可以在本目录的PowerShell中运行：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\启动.ps1
~~~

若8000端口已被占用：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\启动.ps1 -Port 8008
~~~

启动脚本会给出占用端口的进程号与进程名；若占用者是另一个目录的算力沙盘实例，请先在该目录执行 `.\停止.ps1`。

停止由启动脚本启动的后台服务：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\停止.ps1
~~~

停止脚本会连同 venv 派生的子进程与端口监听进程一并结束，并确认端口释放；若仍有残留，会输出进程号并保留 `data\server.json` 供排查。

仅使用源码安装（目录内没有runtime）时，建议使用Python 3.13、Node.js 22.12或更新的兼容版本，执行：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\安装依赖.ps1 -SkipBrowser
~~~

安装脚本使用锁定依赖并构建网页。浏览器自动化仅供开发测试，日常使用不需要安装Playwright浏览器。

## 快速使用

1. 打开项目概览，选择“载入示例项目”体验完整流程，或新建空项目。示例项目只有一份，重复点击是打开同一份（归档后再点才会新建）。
2. 在业务场景页上传.xlsx或粘贴清单，为每个场景选模型、场景类型与算力服务器并填写并发会话数；推理量化精度与工程开销档位在上方「全局配置」统一选一次，对全部场景生效。表格直接给出需求算力与所需卡数。
3. 创新服务页按「全局配置 → 服务规模与模型设置 → 算力汇总」三步：选一张本池算力卡、确认缓存命中率（默认 30%，只折算 Prefill 算力）、填人数与每人月 Token、确认服务模型（默认 DeepSeek-V4-Flash，示例方案也用该模型），页面直接给出卡数、需求算力、月度 Token 与显存下界（不做多模型额度拆分）。效率系数收在「当前生效的工程系数」里，默认收起。开发测试页同样是三步：选本池算力卡 → 选强度档与「需要微调的模型」（单选，默认 DeepSeek-V4-Flash）→ 看卡数、需求算力、槽位与显存；训练系数与档位任务参数默认收起。三池都要出卡数时，各自选一张算力芯片（默认 910C）。
4. 保存方案并开始测算。在结果页查看三池规模、卡数、场景汇总、显存、计算依据和敏感性。
5. 复制方案或修改参数重新计算，比较历史结果。每次计算保留不可变输入和模型快照。
6. 如需粗略费用，先在基线与设置中录入来源明确的人民币单卡报价，再生成费用附录。

## 核心能力

- Excel与文字导入，工作表/表头选择、列映射、单位转换、原始行追踪、重复导入保护。
- 业务场景按推理链路出卡：显存 → Prefill → Decode 三维取最大，再混部利用率抬升与时延回验，不设额外余量。
- 模型结构内置 32 个，支持登记自定义模型；推理量化精度按 W/A/C 三轴独立。
- 同池兼容模型共享权重，三池各自保留资源；开发测试只按微调槽位聚合，不含评测。
- 三池都出物理卡数：卡数 = max(算力卡数, 显存卡数)，按所选芯片折算并换算出等效算力（P，BF16 基准）；芯片未选时该池不出卡数并写明原因。
- 月度Token配额换算，模型份额守恒；开发测试轻度/标准/高强度档位。
- Decimal计算、来源记录、缺失值保留、完整性与依据等级分离。
- SQLite保存项目、历史输入、计算快照、任务状态、基线及报价。
- 参数默认值与说明、版本冲突保护、可撤销操作。
- 规划依据与规划方案组织设计说明，帮助理解计算方法和数据归属。
- 网页结果、敏感性、版本比较、参考卡与价格区间。
- 四张结果卡片支持展开具体数值推导，按当前所选测算快照解释输入、峰值、效率、结构修正、余量与槽位聚合。
- 推理参数可在页面调整：规模上限、卡数聚合与混部、效率系数、时延常数、芯片效率档、敏感度三档，改动存覆盖层，升级默认值不覆盖用户调参。
- 推理评估页按「场景 + 模型 + 量化精度 + 算力服务器」直接给出所需算力与卡数：三维约束取最大、混部利用率抬升、SLA 回验加数据并行；内置 32 个模型结构与昇腾 910B/910C/950 六档规格，支持登记自定义模型。

## 侧栏导航

左侧菜单按大类分组，支持折叠展开（当前页面所属分组自动展开）：

- **算力规划**：项目概览、业务场景、创新服务、开发测试、测算结果、规划依据、基线与设置（7 个二级菜单）。
- **机房布局**：数据中心布局示意图、机房立体布局、机房供电、机房液冷层高承重、液冷微模块布局（5 个二级菜单）。
- **机柜布局**：无二级菜单，按卡数与功率推算机柜组成、机房面积与制冷方案，含平面布局与冷热流动画。
- **ROI 分析**：无二级菜单，测算 CAPEX、折旧、电费运维、Token 单位成本、云比价、盈亏平衡与回收期，支持 Excel 导出。
- **推理评估**：分隔线之下的独立一级模块（For产品组合的集成页面）。

机房、机柜、ROI 三组页面以同源 iframe 嵌入 `frontend/public/` 下的独立工具页（具体目录见「项目架构.md」第 4 节），不读写当前方案与测算快照，不参与「算力结果 → 机柜 → 机房 → ROI」的自动传参。这些页面内容源自开源工程，页面底部统一标注来源与许可说明：本页面包含开源软件 https://github.com/leodus2015-crypto/aidc2026，版权归其各自作者所有，依相应许可证授权。

## 推理评估

侧栏最底部、与主菜单分隔排布的「推理评估」是独立一级模块（For产品组合的集成页面）：内嵌独立的「场景算力评估」工具页，与三池规划互不影响、数据不互通。

1. 页面自带全部预设：28+1 业务场景（按计算形态分组）、32 个主流模型、8+1 昇腾芯片档（910B 两档 / 910C / 950PR 两档 / 950DT 三档 / 自定义卡），打开即预置长任务 Agent 对话、知识库问答、深度推理三个典型场景。
2. 每个场景行选「场景类型 → 模型 → 并发数」即出卡数与主导因素；可展开「调整参数」改输入输出长度、TTFT / TPOT 目标，「计算过程」展开杜邦式逐层拆解（显存 / Prefill / Decode 三约束 → 原始参数）。
3. 全局配置三项：算力卡、推理量化精度（默认 W8A8；BF16 / W8A8 / W4A8，W4A8 仅 950 系可选）、工程开销档位（保守 ×0.8 / 均衡 ×1 / 激进 ×1.2）；「当前生效的工程系数」支持逐项改写并即时重算。创新服务页的「全局配置」选本池算力卡与缓存命中率（默认 30%：命中前缀复用 KV cache，只省 Prefill 算力，Decode 与显存仍按全量上下文），Prefill / Decode 效率（默认 0.35 / 0.15）收在同款「当前生效的工程系数」折叠条里，默认收起；开发测试页选本池算力卡，训练系数（k / ηtrain / adapter 比例）收在同款折叠条里，默认收起。与业务页同一套卡目录，互不影响。
4. 算力汇总按芯片型号分组求和（不同芯片不混算），给出总卡数、服务器台数（8卡/台）与主导因素分布，并附按模型归类明细。
5. 结果只含算力需求量，不含故障冗余等采购侧余量；估算为理论模型加工程经验，验收以现场压测为准。口径与依据见页面底部「估算方法说明」与「估算依据与口径」。

## 业务池与推理链路

业务场景池与「推理评估」用的是同一套引擎：每个场景选模型、推理量化精度、业务场景类型与算力服务器，另填并发会话数，池层汇总各场景的卡数与需求算力。

- 卡数是物理台数，按实例对齐；需求算力以 BF16 稠密算力为基准、按所选推理精度折算，单位 P / T，两者不是同一量纲。
- 三维约束取最大值而不是相加：同一批卡同时承担 Prefill 与 Decode；再按首 Token 与逐 Token 目标回验，不达标逐级加数据并行。
- 容量余量只在池层乘一次（方案顶部的余量设置），场景层不重复加。
- 旧方案与导入清单若只有模型和在线人数，会按模型名匹配等价推理配置并标「旧字段推导」；完全没有模型的场景报待补，不按默认模型硬算。

## 推理参数

「基线与设置 → 推理参数」可调整估算过程中的全部经验系数与常数项：按芯片的 5 项效率系数（Prefill MFU、Decode 带宽利用率、Decode/Prefill 比值、KV 预留、内存预算）、12 项全局工程常数（时延与排队、MoE/Dense 填充效率、Prefill 预算、排队上限等）、三档工程开销系数（保守 ×0.8 / 均衡 ×1 / 激进 ×1.2）。参数结构版本记录在 catalog 的 version 中，接口与计算快照统一回报同一个版本号。

默认值随版本发布在 `backend/app/catalogs/inference_params.json`；页面上的改动作为覆盖层单独保存，升级默认值不会覆盖你的调整，「恢复默认」随时可回。越界值会被拒绝并提示原因，不做静默截断。

## AI设置

当前业务场景页面已移除规划助手，日常规划无需配置AI接口。下述设置仅为保留的后端扩展提供连接信息。

在“基线与设置 → AI连接设置”填写完整对话接口地址、模型名称和可选API Key。接口需支持messages输入和JSON结构化回答，返回choices[0].message.content。

API Key只保留于服务端进程内存；重启后可重新填写，或在启动前设置环境变量PLANNER_AI_KEY。不会将密钥写入数据库、日志或方案快照。

所有业务参数可在页面手动配置并采用默认值；固定计算公式独立于AI接口。实际第三方AI接口需用自己的服务验证。

## 数据与备份

默认数据库位于data/planner.db，支持使用PLANNER_DATA_DIR指定独立数据目录。首次启动自动初始化结构与发布种子模型；结构迁移文件位于backend/migrations。

备份时先停止服务，再复制整个data目录；恢复时将备份放回相同目录后启动。SQLite的WAL日志也属于数据状态，运行中不要只复制单个.db文件。

data/server.log与server-error.log记录服务运行信息。服务默认只监听127.0.0.1。

## 口径与当前边界

P/T 是算力单位（1 T = 10^12 FLOPS，1 P = 1000 T = 10^15 FLOPS）；本产品的算力基准为 BF16 稠密等效，精度基准单独标注（BF16 / FP16 / FP8），不同原生精度不会按位宽自动换算。效率、请求频次、档位与部分显存预算属于C级经验假设。所有结果用于早期规划，响应时间和设备互联条件需要后续实测校准。

缺少可靠基线的任务保留并标记未计入，不以0补齐。图文模型使用明确标记的视觉与混合缓存代理；特殊压缩缓存可只给权重下界。QLoRA没有量化元数据预算时会显示待补基线。

参考卡价格初始为空。费用仅含加速卡购置，未核验大陆实际供给、互联拓扑或整机配置。当前实现不包含账号审批、设备部署、真实Token发放和文档导出。

设计依据及开发任务见docs目录；验证结果见[测试报告](docs/测试报告.md)，核验来源见[模型基线核验](docs/模型基线核验.md)。
