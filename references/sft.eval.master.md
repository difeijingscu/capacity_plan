## 1. 整体估算链路

```
① 模型（激活参数/架构）─┐
② 微调方式（全参/LoRA）─┤
③ 数据配置（样本×轮×序列）─┼→ Token 总量 → 总 FLOPs → 有效算力 → 双模式输出
④ 芯片（峰值算力/显存）─┤                            ├─ 模式 A：定耗时 → 求卡数（显存下限 + 副本对齐）
⑤ 效率档（乐观/中性/保守）─┘                            └─ 模式 B：定卡数 → 求耗时（TP×PP×DP 可行性校验）
```

输出辅助模块：屋顶线（Roofline）分析、模型参数量结构校验、告警体系、推荐卡数网格、乐观–保守区间。

> 注意 UI 与内部命名相反：页面 tab「模式 A — 设定耗时，评估卡数」内部为 mode `b`；「模式 B — 规划卡数，评估耗时」内部为 mode `a`。本文档按 UI 语义称呼。

### 2.2 微调方式

- **全参 Full SFT**：更新全部参数。
- **LoRA**：
  - LoRA Rank，默认 **64**（范围 1–4096）；

## 3. 核心计算口径

### 3.1 微调 Token 总数

```
Token 总数 T = 样本条数 × 平均序列长度 × 轮数 Epoch × 打包效率 packEff
```

### 3.2 总计算量（FLOPs）

**全参微调：**

```
总 FLOPs = 6 × 激活参数量 N × T × 重计算系数 × 杂项开销
           × (1 + 2 × 序列长 × 注意力宽度 × 层数 ÷ N)
```

**LoRA 微调：**

```
总 FLOPs ≈ (4 × N + 2 × LoRA 可训量) × T × LoRA重计算系数 × 杂项开销
           × (1 + 3 × 序列长 × 注意力宽度 × 层数 ÷ N)
```

脚本实际实现为两项相加再乘开销：

- 参数路径：全参 = 前向 2N + 反向 4N = 6N；LoRA = 前向 2N + 反向（链式 2N + 适配器权重梯度 2L）= 4N + 2L。
- 注意力额外项（**全参与 LoRA 同一系数**）：`12 × seq × 注意力宽度 × 层数 × T`。
  - 上面 (1+2×)/(1+3×) 只是 12 分别除以 6N / 4N 的代数变形。
- 注意力宽度：= Q 头数 × 头维；**MLA = 头数 × (qkNope + qkRope)**（低秩只用于 KV cache，不用满宽隐层）。GQA 时宽度仍按 Q 侧满宽计。
- 序列越长注意力项占比越大，长序列场景不可忽略。

**关键结论**：LoRA 相对全参只少反向权重项 2N，长序列下总计算量往往只少 **15–35%**；**LoRA 的主收益在显存而非算力**。

### 3.3 LoRA 可训参数量推导

每层（Rank = r）：

```
Q 投影适配器  J = r × (hidden + qDim)      qDim = 注意力宽度（MLA 时用 qLora）
KV 投影适配器 X = r × (hidden + kvDim)     kvDim = GQA: KV头数×头维；MHA: hidden；MLA: kvLora
注意力部分/层 = a×J + b×X                  Q+V: a=1,b=1（Q 侧 1 矩阵、KV 侧 1 矩阵）
                                          QKVO: a=2,b=2（Q/O 侧 2 矩阵、K/V 侧 2 矩阵）
FFN 部分/层   = ffn矩阵数 × r × hidden × (1 + moeFfn)    6目标→2矩阵；7目标→3矩阵
                                          MoE 用专家宽比 moeFfn，非稠密 FFN 扩张比
显存口径 LoRA 量 = 注意力 + FFN ×（勾选覆盖全专家时 × 专家总数）
算力口径 LoRA 量 = 注意力 + FFN ×（MoE 勾选全专家时 × Top-K）
```

### 3.4 开销系数

| 系数 | 取值 | 说明 |
|---|---|---|
| 重计算系数 | GC 关闭 1.00；Selective：**FA 开 1.05 / FA 关 1.08**；Full 1.33 | LoRA 模式下（GC=Full 或系数 ≥1.2）按 `1 + 1.5×(系数−1)` 折合（1.33 → ≈1.50） |
| 杂项计算开销 | 默认 1.01；QLoRA 时 ≥1.08 | 裁剪、归一化、反量化等 |
| MoE 通信折合 | 默认 1.00（已含在 MFU 里） | **只除有效算力拉长时间，不计入总计算量** |
| MoE 路由折合 | 默认 1.00 | 同上 |

总开销 = 重计算 × 杂项。页面同时展示折合系数 k ≈ 总 FLOPs ÷ (N × T)（含 MoE 时 k 再乘 MoE 系数），作为每 token 等效倍数的展示口径。

## 4. MFU 算力利用率模型

```
MFU = clamp( 基础值(架构/规模) + 芯片修正 + 精度修正 + 集群修正 + 档位偏移, 18%, 55% )
      × 集群规模对数衰减
```

- **基础值**（dense，按激活参数量）：≥100B → 40；≥65B → 38；≥30B → 36；≥13B → 38；≥7B → 40；其余 36
- **基础值**（MoE）：≥30B → 28；≥10B → 30；其余 32
- **修正项**：LoRA −2；910B −3 / 910C-626T +1 / 950 系列 +2 / 910C-560T 0；FP8 −3；集群 ≥512 卡 −2、≥64 卡 −1、≤8 卡 +2
- **集群规模衰减**：按 **参数量(B) ÷ 卡数 > 20**（即单卡承担参数量超 20B）后，`× max(0.35, 1 − 0.355×(log10(比值) − log10(20)))`，下限 ×0.35
- 三档预设叠加 ±6 偏移；MFU 手动滑条范围 10–90%（参与计算的值仍被 clamp 到 18–55）
- 手动设定 MFU 后，卡数迭代不再自动改写 MFU

## 5. 卡数与耗时推导（双模式）

### 5.1 模式 A — 设定耗时，评估卡数

```
卡数 = ⌈ 总FLOPs ÷ (单卡峰值TFLOPS × 10¹² × MFU × 目标小时 × 3600 ÷ MoE通信折合) ⌉
```

流程：
1. **迭代收敛（最多 8 轮）**：卡数变化 → 集群规模衰减使 MFU 变化 → 重算卡数，直至稳定（用户手动设过 MFU 则不迭代）。
2. **显存下限卡数**：二分搜索（上限 65536 卡）能装下的最少卡数，再按 TP×PP 向上对齐完整副本；取 max(算力卡数, 显存下限)。若 65536 卡仍装不下 → 告警「单卡显存过小」。
3. **装不下降级**：优先降微批 → 再降 GA → 最后才加卡（加卡按 TP×PP 倍数对齐向上搜索）。
4. **副本对齐（最多 8 轮迭代）**：卡数向上取整到 **TP×PP×EP** 完整副本的倍数；闲置卡数单独提示（有效算力按实际部署卡数计）。

### 5.2 模式 B — 规划卡数，评估耗时

```
有效算力 = 卡数 × 单卡峰值 × 10¹² × MFU ÷ MoE通信 × (集群效率×流水线效率，仅勾选时)
耗时(小时) = 总FLOPs ÷ 有效算力 ÷ 3600
```

- **流水线气泡修正**：PP>1 时 利用率 = GA ÷ (GA + PP − 1)。**注意：该修正与集群效率共用同一个「再计入集群效率与流水线气泡」开关，默认关闭**（默认口径：MFU 已含端到端损耗）。
- 模式 B 流程：初算耗时 → 迭代（最多 10 轮，重算 PP 与流水线效率）→ 显存装不下时降微批/GA（**不自动加卡**，卡数由用户给定）。
- 模式 B 不做显存下限二分与副本对齐（那是模式 A 专属）。
- TP×PP > 规划卡数时告警「并行度数与 GPU 数不匹配」。

### 5.3 输出指标

- 总计算量（PFLOPs / EFLOPs / ZFLOPs 三级换算）、系统有效算力（TFLOPS/PFLOPS）、总训练步数 = ⌈样本×Epoch ÷ (微批×GA×DP)⌉、每步耗时（ms/s/min）= 总FLOPs ÷ 步数 ÷ 有效算力、总耗时（分钟/小时/天/月自适应）、GPU-days。
- **推荐卡数网格**：围绕对齐后的副本数给出约 5 个候选卡数（各带拓扑与预估耗时，标记推荐项）。
- **乐观–保守区间**：自动以乐观/保守两档整套重算并回填当前状态，给出区间（模式 A 输出卡数区间、模式 B 输出耗时区间）。
- 每步 Token = 微批 × seq × GA × DP。

## 6. 显存模型（决定下限卡数）

### 6.1 单卡显存组成

```
显存 = 参数 + 梯度 + 优化器状态 + 激活显存 + MoE 通信缓冲
```

**字节口径（训练精度）**：storB = 参数字节 pb + 梯度字节 4 + Adam 12

| 精度 | 参数字节 pb | 梯度字节 | 优化器（Adam） | 合计 storB |
|---|---|---|---|---|
| BF16/FP16 | 2 | 4 | 12 | 18 |
| FP8 | 1 | 4 | 12 | 17 |
| FP32 | 4 | 4 | 12 | 20 |
| QLoRA 底座 | 0.5（NF4） | — | 仅 adapter | — |

单位换算：GB 参数显存 = 参数量(B) × 10⁹ × 字节 ÷ 1024³。

**全参**：参数/梯度/优化器覆盖全量参数。MoE 把参数拆为「非专家部分」与「专家部分」（专家部分 = 总参 − 激活 − 非专家，按专家均摊）分别切分：参数按 TP×PP 切（ZeRO-3 再按 DP 切；专家额外按 EP 切）；梯度按 TP 切（ZeRO-2+ 再按 DP 切）；优化器始终按 DP 切（ZeRO-1+）。

**LoRA**：
- 冻结底座参数只按 **TP×PP** 切（专家加 EP），**不参与 ZeRO**；
- 适配器参数按训练精度字节存，**不做切分**；
- 适配器梯度（4B）：适配器 ZeRO-2 时按 DP 切；
- 适配器 Adam（12B）：始终按 DP 切；
- **适配器 ZeRO 触发条件**：适配器参数显存 ÷ (TP×PP) > 30% 单卡显存 → ZeRO-2，否则 ZeRO-1（LoRA 最高到 2）。

### 6.2 激活显存（每 microbatch 每卡）

按 GC 模式三档：

- **Full GC**：`2 × 层数 × seq × 微批 × hidden`（每层只存输入，反向逐层重算；与重计算系数 1.33 同源）
- **Selective**：逐层激活 × **0.3**（保留约 30% 中间激活）× 层数
- **关闭**：`微批 × seq × hidden × (10 + (2 + 11×KV系数) ÷ TP)`；**Flash Attention 关闭时额外加 `5 × Q头数 × seq ÷ (hidden × TP)`**（对应注意力分数 O(s²) 项；KV系数 = 2 × KV头数 ÷ Q头数）

折算：开启序列并行时 ÷ min(SP, TP)（沿 TP 域切）；PP>1 时 ÷ 流水线驻留系数（PP ÷ 在飞微批数，即首段驻留时不摊薄）。最后 × 激活守卫（1.10/1.12/1.15）。

### 6.3 MoE 通信缓冲

```
微批 × 激活专家 Top-K × seq × hidden × 2字节 × 2(双缓冲) ÷ EP
```

AllToAll 双缓冲，按 EP 分片；Dense 无此项。

### 6.4 ZeRO 分级（全参自动）

按切分后单卡参数占显存比例：
- 占比 > 85% → **ZeRO-3**（参数+梯度+优化器全切片）
- 占比 > 55% → **ZeRO-2**（梯度+优化器切片）
- 否则 → ZeRO-1（仅优化器切片）

### 6.5 安全余量与判定

- 可用显存 = 标称 × (1 − 预留)（乐观 6% / 中性 7% / 保守 8%）
- 门控判定：`显存需求 ≤ 标称×(1−预留)`；展示口径：估算值 + 激活×守卫 + 预留
- 状态三色：充足 / 紧张（>85% 可用显存）/ 超出容量 / 余量不足
- 装不下降级顺序：**降微批 → 降 GA → 加卡**（模式 A）；模式 B 只降批次不加卡

## 7. 并行策略引擎

- **world = TP × PP × DP**；**EP 从 DP 中划分，不再另乘**；本页不做推理侧 Prefill/Decode 分离。
- **TP**：候选 {1,2,4,8}，需整除 Q 头数（GQA 且 KV<Q 时还需整除 KV 头）。结构下限：
  - LoRA：MLA → 1；hidden≥8192 或 heads≥128 或总量≥400B → 4；hidden≥5120 或 heads≥64 或总量≥70B → 2；否则 1
  - 全参：MLA → 1；hidden≥7168 或 heads≥128 或总量≥200B → 8；hidden≥5120 或 heads≥64 或总量≥70B → 4；hidden≥4096 或 heads≥32 或总量≥30B → 2；否则 1
- **PP**：候选 {1,2,4,8,16} 且 ≤ 层数÷8；仅全参触发：总量≥200B 且 ⌈卡数÷8⌉≥8 → 4；(总量≥100B 且段≥4) 或 参数/TP/PP 单卡 >1.2×显存 → 2。
- **EP**：从 DP 中划分。目标值：DP≥64 → 4、DP≥16 → 2、否则 1；要求 DP % EP == 0、EP ≤ 专家数、EP ≤ 64；MoE 时 EP 接近专家数平方根量级打分更优。
- **SP 序列并行**：按序列长度自动（≤8K → 1、≤16K → 2、≤32K → 4、>32K → 8），沿 TP 域切分且不超过 TP；可手动开/关。
- **自动推荐打分**（枚举 TP×PP 组合）：
  - 显存装得下 +1000；装不下 −min(240, 2.2×超出量)
  - 副本利用率 +used/卡数×16；闲置卡 −0.25×闲置数
  - PP 气泡 −(PP−1)×(LoRA 28 / 全参 14)
  - TP 低于下限 −36×档差；高于下限 −6×log2(倍数)
  - EP 偏离目标 −10×|log2(EP/目标)|；EP=1 且 DP≥4 且专家≥16 → −18；DP % EP ≠ 0 → −40
  - 装得下但显存 <88% 可用 → +4
  - 取最高分；可手动指定 TP/PP/EP（引擎照常给出推荐值对照）。

## 8. 辅助输出模块

### 8.1 屋顶线（Roofline）分析

```
算术强度 AI = 单步FLOPs ÷ 单步Bytes
单步Bytes = (权重读2次 × pb + 梯度1次 × 4B) 按 TP×PP(×EP) 分片后 × 实际卡数
屋脊点 = 单卡峰值TFLOPS ÷ HBM带宽(GB/s)  → FLOPs/Byte
AI ≥ 屋脊点 → 计算受限（理想）；AI < 屋脊点 → 访存受限（建议增大 Batch）
```

### 8.2 模型参数量结构校验

按用户输入的结构参数从零重建总参/激活参并与输入值对拍：

```
每层注意力参数：
  MHA/GQA: hidden×(Q头×头维) + hidden×(KV头×头维)×2 + (Q头×头维)×hidden
  MLA: hidden×qLora + qLora×Q头×(qkNope+qkRope) + hidden×(kvLora+qkRope)
       + kvLora×Q头×(qkNope+vDim) + Q头×vDim×hidden
每层 Dense FFN = 3 × hidden × (ffnRatio × hidden)
MoE 每 expert = 3 × moeLatent(默认hidden) × expertHidden(默认 moeFfn×hidden)
共享专家 = 3 × hidden × expertHidden；若显式 moeLatent < 0.75×hidden → 3 × 2 × hidden × moeLatent
词嵌入 = vocab × hidden × 2（tieEmbed 时 ×1）
总参 = Dense层×(attn+稠密FFN) + MoE层×(attn+全expert+共享) + MTP层×(MoE结构) + 词嵌入
激活参 = MoE 层按 Top-K 计激活专家（非 ×E），其余同上
```

偏差 >15% 时提示核对隐层、层数、FFN 比、词表、专家数/Top-K、MLA 低秩维。自定义模型必看。

### 8.3 告警体系（按严重度排序展示）

| 级别 | 触发条件 |
|---|---|
| danger | 单卡显存过小（加到 65536 卡仍装不下）；显存估算 > 单卡标称 |
| warning | 显存余量不足（门控不过）；TP×PP > 规划卡数；总耗时 > 168h（建议加卡或减 epoch）；总步数 < 100（训练不会收敛：样本/轮数太少或 DP 太大） |
| info | 自动降微批说明；LoRA rank > 256；序列并行已启用 |

### 8.4 输入校验

所有数值输入带默认值与上下限，非法输入自动按边界修正并列出修正清单（最多显示 4 条）；KV 头 > Q 头、Top-K > 专家数自动裁剪。

## 10. 关键设计原则（供 ComputePlanner 复用）

1. **算力计费以激活参数量为口径**，MoE 模型总参数只影响显存与专家并行划分。
2. **LoRA 不省算力省显存**：长序列下 FLOPs 仅少 15–35%，但优化器/梯度显存大幅下降。
3. **MoE 通信开销写在分母**：只拉长时间，不夸大总计算量，与预训练同一口径。
4. **显存是硬约束、算力是软约束**：先按算力反推卡数，再用显存下限兜底，最后按并行副本对齐。
5. **装不下优先降批次（微批→GA），不降模型切分**，避免无谓加卡。
6. **双模式互为校验**：模式 A 的卡数 ↔ 模式 B 的耗时，同一套 FLOPs 与有效算力公式。
7. **三档预设本质是 MFU/重计算/杂项/预留/守卫的组合偏移**，而不是改公式。
8. 明确声明**理论估算 ≠ POC 实测**，输出为预算量级，不作为验收依据。
9. **总步数下限保护**：全局批次上限 min(1024, 样本×Epoch÷100)，保证 ≥100 步；步数过少告警"卡数并不是越多越好"。
10. **默认口径最简**：集群效率与流水线气泡默认不计入（MFU 视为端到端口径），需要拆解时手动开启。
