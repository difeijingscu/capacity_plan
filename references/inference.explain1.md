## 1. 整体估算链路

与微调工具不同，推理评估是**多约束取 max + SLA 回验**的结构：

```
输入（模型/量化/场景/芯片/工程开销）
   ↓
A 显存约束卡数 —— 权重、激活、KV 能否装下
B Prefill 约束卡数 —— 按目标 TTFT / Prefill 吞吐估最少卡
C Decode 约束卡数 —— 按目标 TPOT / Decode 吞吐估最少卡
   ↓ 物理下界 = max(A, B, C)（混部时校验 Prefill+Decode 利用率之和 ≤100%，超出则抬升）
D SLA 规划加卡 —— 并行拓扑落地后按预测时延再验，不达标再加实例
   ↓
综合推荐卡数（另附 扩容余量 +20% 与 PD 分离/混部形态判定）
```

## 3. 显存约束卡数（维度 A）

### 3.1 KV Cache 每 token 字节

```
MHA/GQA：kvGB/tok = 2 × 层数 × (KV头数 × KV头维) × KV精度字节 ÷ 10⁹
MLA：    kvGB/tok = 层数 × (MLA低秩维 + 旋转位置维) × KV精度字节 ÷ 10⁹
混合注意力：有效层数 = 层数 × 全注意力层占比；
          含滑动窗口时 占比折算 = m + (1−m) × min(1, 窗口/序列长)
```

KV 等效比展示：MLA vs MHA = (latentDim+ropeDim) / (2×Q头数×headDim)。

### 3.2 显存约束卡数推导

```
① 单卡可用显存 = 单卡显存 × HBM 容量利用率（默认 90%）
② 权重装载下界 = ⌈模型总参 × W字节 ÷ 单卡可用⌉
③ 单实例 = TP×PP×EP 组合（自动枚举）；单实例 KV 可用显存
   = 实例卡数 × 单卡可用 − 权重（MoE 按 TP×PP×EP 切分、专家命中折算）− 激活
④ 当前 KV 需求 = kvGB/tok × 并发 × 预留长度 × KV 预留系数(110%)
⑤ 所需实例数 = ⌈KV 需求 ÷ 单实例 KV 可用⌉
   显存约束卡数 = max(权重装载下界, 实例数 × 单实例卡数)
```

- **MoE 权重切分**：非专家参数 ÷ (TP×PP)；路由专家 ÷ (TP×PP×EP)，并按路由命中率折算实际装载（命中率随 EP/专家数，含偏斜系数 1.08）。
- PP 惩罚系数：PP=2 → ×1.15，PP=3 → ×1.25，PP≥4 → min(1.5, 1.2+0.05×(PP−4))。
- 枚举打分时 PP>2 每级 +6%、EP 按模式 +2%/8%·log2(EP) 惩罚，取总卡数最小解。

## 4. Prefill 约束卡数（维度 B）

### 4.1 Prefill FLOPs

```
GEMM 主项  = 2 × 激活参数量 × 有效Prefill token数 ÷ FFN利用率修正
注意力项   = GQA/MHA：4 × 层数 × Q头数×头维 × 新token × 平均跨度
            MLA：2 × 层数 × (qkNope+rope 折算) × 新token × 平均跨度
有效 Prefill token = 输入 × (1 − Prefix 命中率) + 前缀残余(×0.1 计入 FFN)
平均跨度 = 前缀 + (新token+1)/2，再经注意力跨度/滑窗折算
```

**FFN 利用率修正**（MoE 专家块在小批量下填不满）：
- MoE：`fill = 1 − exp(−批量×min(topK,8)/专家数 ÷ 800)`，映射到 0.07–0.5 区间，EP>1 最多再 ×1.15
- Dense：`0.42 + 0.58×(1 − exp(−token数/5500))`

**Prefill MFU**：随单步批 token 数 n 的饱和曲线——`基础MFU × max(0.45, 0.45+0.55×(1−e^{−n/512})×√min(1,n/128)) × 0.72`，下限 5%。

### 4.2 两个卡数取 max

```
吞吐约束卡数 = ⌈单请求FLOPs × 需求QPS ÷ 有效算力 ÷ 长序列修正⌉
              长序列修正 = 1 + 0.12×log2(序列/16K)
时延约束卡数 = ⌈单请求FLOPs ÷ (有效算力 × TTFT预算秒)⌉
              TTFT 预算先扣 Prefill 引擎固定开销；预算上限 10s（TTFT>15s 时放宽到 60s）
              超过单机 TP 上限（8 卡）则标记 TTFT 物理不可行
N_prefill = max(吞吐约束, 时延约束)
```

Prefill 受限判定：比较计算强度 OI 与拐点（算力/带宽），OI < 拐点则**带宽受限**（HBM 读权重+KV 主导）。

## 5. Decode 约束卡数（维度 C）

### 5.1 每 token FLOPs 与带宽时间

```
每 token 线性层 FLOPs = 2 × 激活参数量
每 token 注意力 FLOPs = 4 × 层数 × Q头×头维 × 当前KV长度（MLA 按低秩折算）
Decode 每步带宽时间 = 权重读 ÷ (带宽×uWeight) + 批量KV读 ÷ (带宽×uKv)
   MoE：共享专家 ÷(TP×EP) + 路由专家×命中率 ÷(TP×EP)，用 uMoe 档
```

**Decode MFU**：`Prefill MFU × 0.58/0.66（随芯片）`，再按批量饱和曲线 `×(0.6 + 0.4×(1−e^{−batch/4})) × 1.25`。

### 5.2 TPOT 逐步合成

```
TPOT = max(带宽时间, 计算时间×批拥挤系数, MoE A2A 通信)
     + 重叠惩罚 × (三项和 − max)
     + TP AllReduce 通信 + PP 气泡 + Decode 调度固定开销(≈1.35ms) + KV walk(MoE≥15B)
批拥挤系数 = 1 + 0.07×log2(有效批量)
PP 气泡 ≈ 0.8×(PP−1)/副本数 级别
```

**TPOT 理论下限**：权重一遍读 ÷ (TP×EP×带宽×uWeight)——低于此值加卡无效，工具直接标记「已达本芯片显存带宽理论下限」。

N_decode 为同时满足 TPOT 目标与带宽下界的最少卡数（含 A2A 约束分档）。

## 6. TTFT / 排队 / 并发模型

### 6.1 TTFT 合成

```
TTFT = Prefill roofline 服务时间 + 排队等待 + 混部调度等待
roofline 服务时间 = max(计算时间, HBM 时间, 通信时间)
                  + 0.4×(三项和−max) + 引擎固定开销(随层数/卡数/输入长)
排队等待 = max(Prefill 排队残余, 批槽位等待)；混部调度等待另计
```

- 排队用类 M/G/c 迭代近似：利用率 ρ = 到达率×服务时间（封顶 0.95），残余等待 ≈ 0.5×服务时间×ρ。
- 批槽位占用倍数 = ⌈并发 ÷ max_num_seqs⌉，槽位超额时等待按倍数线性放大。
- 混部时 Decode 被 Prefill 插入打断：插入惩罚 ≈ Decode 步长 × min(0.2, …)。

### 6.2 并发上限（四约束取最小，二分搜索）

| 上限 | 口径 |
|---|---|
| 显存 KV | 可用 KV 显存 ÷ 每路 KV 需求 |
| 批槽位 | ⌊DP 副本数 × max_num_seqs ÷ 槽位占用⌋ |
| 吞吐 | ⌊每副本输出 TPS × 副本数 × TPOT目标 ÷ 槽位⌋ |
| 时延 | 二分搜索满足 TTFT/TPOT（含排队恶化的最大并发） |

达标判据：预测 ≤ 目标 ×1.00（严格）；容差 ×1.10 仅作加卡停机（容差内不算达标）。并发判据：可支撑并发 ≥ 需求 ×1.00；供给 QPS = 副本数 × 每副本 TPS（多副本 ×0.95）。

## 7. 并行策略与 PD 分离

### 7.1 拓扑搜索

- TP 候选按整除约束枚举（机内上限 8）；MoE 偏好 TP 整除专家相关结构；PP 仅在大模型/显存不足时启用；EP 分「容量向（≤16）」与「生产向（≤64，含 32/64/128/256 宽 EP）」两种模式，自动模式按 专家数≥64 且 总参/激活≥8 且 TopK≥8 判生产向。
- 打分：偏离显存最优 TP/PP 扣分、偏离推荐 TP 扣分、PP 气泡扣分、EP 过小/过大扣分，总卡数膨胀 ×1.02 以上再扣分；同分比 stepMs/TTFT 实测估值。

### 7.2 PD 分离判定（四闸门 + 四动机）

**任一闸门命中 → 不建议分离**：
1. 互联：单请求 KV 跨池搬运 > TTFT 预算的 30%
2. 规模：混部下界 < 16 卡（池化收益摊不平，业界实测反掉 20–30%）
3. 短输出：输出 ≤ 64 token（Dense ≤128）
4. Dense 权重：Dense 且输入 < 32K（两池各持一份权重摊不平）

**动机命中越多越倾向分离**：
1. Prefill 重载：Prefill 时间片 ≥35% 且 TPOT ≤ 60ms（双紧 SLO）
2. 混部重叠：Prefill+Decode 利用率之和 > 100%
3. 拓扑冲突：输入 ≥4K 且 ≥32 卡（P 侧要大 TP 压 TTFT，D 侧要小 TP 大 DP）
4. 超大规模：≥128 卡且输入 ≥4K

分离后 P 池按 TTFT 定卡、D 池吸收显存约束并满足 TPOT，跨池 KV 搬运时延计入 TTFT。

## 8. 最终卡数合成

```
物理下界 = max(A 显存, B Prefill, C Decode)
  混部校验：Prefill 利用率 + Decode 利用率 > 100% → 按超出比例抬升下界
SLA 加卡：在物理下界上落并行拓扑（TP×PP×EP×DP），预测 TTFT/TPOT/并发；
  不达标时优先加 DP 实例，仍不达标且 TTFT 受限 → 提升 TP（机内上限内）；
  TPOT 达带宽理论下限 → 提示放宽目标/换高带宽芯片/换小模型
综合推荐 = 拓扑对齐后的 SLA 达标卡数（奇数强制补偶，对齐副本整数倍）
扩容余量 = 推荐 × 1.2 再按单实例卡数向上取整
```

输出另含：服务器台数（8 卡/台）、服务形态（混部/PD 分离）、各维度卡数分解、瓶颈标注（显存/Prefill/Decode）、供给与需求 QPS、显存利用率、风险提示。

## 10. 关键设计原则（供 ComputePlanner 参考）

1. **推理是四维约束取 max**：显存、Prefill（TTFT）、Decode（TPOT）、SLA 回验，与微调「总算力 ÷ 有效算力」的单维口径本质不同。
2. **显存看总参、算力看激活参**：MoE 推理显存装全部专家，计算只走激活部分。
3. **W/A/C 三轴量化分离**：权重定显存、激活定峰值算力、KV 定并发容量；INT4 仅在 950 上给原生峰值。
4. **Decode 是带宽游戏**：TPOT 下限由「权重+KV 读取 ÷ HBM 带宽」决定，加算力无效；Prefill 是算力/带宽 roofline 取 max。
5. **KV Cache 是并发容量的核心变量**：MLA（低秩+rope）相对 MHA 可压缩 KV 一个量级，混合注意力按全注意力层占比折算。
6. **排队不能忽略**：TTFT = 服务时间 + Prefill 排队 + 批槽位等待 + 混部打断；高并发下排队主导。
7. **PD 分离有明确闸门**：<16 卡、短输出、弱互联、Dense 短输入都不该分；分离是为「Prefill 不打断 Decode」买稳定性，不是省卡手段。
8. **Prefix Cache 只省计算不省 KV**：命中部分仍占 KV 显存且 TTFT 要回读。
9. 所有 MFU/带宽利用率/拥挤系数均为工程经验值（随芯片分档），工具明确声明非 POC 实测，规划结论需压测校验。
