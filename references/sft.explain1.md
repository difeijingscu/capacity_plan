## 1. 整体估算链路

```
① 模型（激活参数/架构）─┐
② 微调方式（全参/LoRA）─┤
③ 数据配置（样本×轮×序列）─┼→ Token 总量 → 总 FLOPs → 有效算力 → 双模式输出
④ 芯片（峰值算力/显存）─┤                            ├─ 模式 A：定耗时 → 求卡数（显存下限 + 副本对齐）
⑤ 效率档（乐观/中性/保守）─┘                            └─ 模式 B：定卡数 → 求耗时（TP×PP×DP 可行性校验）
```

## 3. 核心计算口径

### 3.1 微调 Token 总数

```
Token 总数 T = 样本条数 × 平均序列长度 × 轮数 Epoch × 打包效率 packEff
```

### 3.2 总计算量（FLOPs）

**全参微调（更新全部参数）：**

```
总 FLOPs = 6 × 激活参数量 N × T × 重计算系数 × 杂项开销
           × (1 + 2 × 序列长 × 注意力宽度 × 层数 ÷ 激活参数量)
```

**LoRA 微调（仅更新少部分可训练参数）：**

```
总 FLOPs ≈ (4 × N + 2 × LoRA 可训量) × T × LoRA 重计算系数 × 杂项开销
           × (1 + 3 × 序列长 × 注意力宽度 × 层数 ÷ 激活参数量)
```

**6N 口径拆解**：前向 ≈ 2N；反向 ≈ 4N（激活梯度 2N + 权重梯度 2N）。
**LoRA 4N+2L 口径**：底座冻结、无权重梯度项（少 2N），反向 = 链式 2N（底座）+ 2×LoRA 可训量。

**注意力修正项**（脚本实现为加项 `12 × seq × attnWidth × layers × T`）：
- 注意力宽度 = Q 头数 × 头维；**MLA = 头数 × (qkNope + qkRope)**。
- 序列越长，注意力项占比越大（长序列场景不可忽略）。

**关键结论**：LoRA 相对全参只少反向权重项 2N，长序列下总计算量往往只少 **15–35%**，**LoRA 的主收益在显存而非算力**。

### 3.3 LoRA 可训参数量推导

```
Q 投影适配器  J = r × (hidden + qDim)        （MLA 时 qDim 用 qLora 折算）
KV 投影适配器 X = r × (hidden + kvDim)       （MLA 时 kvDim 用 kvLora 折算）
注意力部分 = (a×J + b×X) × 层数              （Q+V：a=1,b=1；QKVO：a=2,b=2）
FFN 部分   = ffn矩阵数 × r × hidden × (1 + moeFfn) × 层数
显存口径 LoRA 量 = 注意力 + FFN ×（覆盖全专家时 × 专家总数）
算力口径 LoRA 量 = 注意力 + FFN ×（MoE 全专家时 × Top-K）
```

### 3.4 开销系数

| 系数 | 取值 | 说明 |
|---|---|---|
| 重计算系数 | GC 关闭 1.00；Selective 1.05（MoE）/1.08；**Full 1.33** | LoRA 开全量 GC 时按 `1 + 1.5×(系数−1)` 折合（≈1.50） |
| 杂项计算开销 | 默认 1.01；QLoRA 时 ≥1.08 | 裁剪、归一化、反量化等 |
| MoE 通信折合 | 默认 1.00（已含在 MFU 里） | **只写在分母拉长时间，不计入总计算量** |
| MoE 路由折合 | 默认 1.00 | 同上 |

总开销 = 重计算 × 杂项；右侧折合系数与预训练同一口径。

## 4. MFU 算力利用率模型

```
MFU = clamp( 基础值(模型规模/架构) + 芯片修正 + 精度修正 + 规模修正, 18%, 55% ) × 集群规模对数衰减
```

- **基础值**（dense）：≥100B → 40；≥65B → 38；≥30B → 36；≥13B → 38；≥7B → 40；其余 36
- **基础值**（MoE）：≥30B → 28；≥10B → 30；其余 32
- **修正项**：LoRA −2；910B −3 / 910C-626 +1 / 950 系列 +2；FP8 −3；集群 ≥512 卡 −2、≥64 卡 −1、≤8 卡 +2
- **集群规模衰减**：卡数/参数量之比 >20 后按 log10 对数衰减（下限 ×0.35）
- 三档预设再叠加 ±6 偏移

## 5. 卡数与耗时推导

### 5.1 模式 A — 设定耗时，评估卡数

```
卡数 = 总FLOPs ÷ (单卡峰值TFLOPS × 10¹² × MFU × 目标小时 × 3600 ÷ MoE通信折合)
```

1. 迭代收敛（最多 8 轮）：卡数变了 → MFU 随集群规模变 → 重算卡数直至稳定。
2. 计算**显存下限卡数**（二分搜索能装下的最少卡数），取两者较大值。
3. **副本对齐**：按 TP×PP×DP 取整倍数，向上对齐。

### 5.2 模式 B — 规划卡数，评估耗时

```
有效算力 = 卡数 × 单卡峰值 × 10¹² × MFU ÷ MoE通信 × 流水线利用率
耗时(小时) = 总FLOPs ÷ 有效算力 ÷ 3600
```

- **流水线气泡修正**：PP>1 时 利用率 = GA / (GA + PP − 1)。
- 集群效率（乐观 96% / 中性 90% / 保守 80%）默认不计入，开启后乘在分母。

### 5.3 输出指标

总计算量（EFLOPs/ZFLOPs）、系统有效算力（PFLOPS）、总训练步数、每步耗时（ms）、总耗时；推荐卡数方案按并行副本对齐，给出乐观–保守区间。

## 6. 显存模型（决定下限卡数）

### 6.1 单卡显存组成

```
显存 = 参数 + 梯度 + 优化器状态 + 激活显存 + MoE 通信缓冲
```

**字节口径（训练精度）**：

| 精度 | 参数字节 pb | 梯度字节 | 优化器（Adam） | 合计存储 storB |
|---|---|---|---|---|
| BF16/FP16 | 2 | 4 | 12 | 18 |
| FP8 | 1 | 4 | 12 | 17 |
| FP32 | 4 | 4 | 12 | 20 |
| QLoRA 底座 | 0.5（NF4） | — | 仅 adapter | — |

- 全参：参数/梯度/优化器均覆盖全量参数（MoE 非专家参数与专家参数分开按 TP/EP 切分）。
- LoRA：底座只占参数字节（QLoRA 0.5B），梯度/优化器仅覆盖 adapter。

### 6.2 激活显存（Re 函数）

按 GC 模式三档（每 microbatch 每卡）：
- **Full GC**：`2 × 层数 × seq × 微批 × hidden`（仅存输入，最小）
- **Selective**：核心注意力模块重算，其余保留
- **关闭**：`微批 × seq × hidden × (10 + (2 + 11×KV/Q比) ÷ TP)`；**标准 Attention 额外加 `5 × TP × seq² ÷ hidden`** 项（Flash Attention 去掉该平方项）
- 流水线 PP 按在飞微批数折算（PP 气泡相关 div 系数）；SP 开启时按 TP 路切分。

### 6.3 ZeRO 分级（自动）

按并行切分后单卡参数占显存比例：
- 占比 > 85% → **ZeRO-3**（参数+梯度+优化器全切片）
- 占比 > 55% → **ZeRO-2**（梯度+优化器切片）
- 否则 → ZeRO-1（仅优化器切片）

### 6.4 安全余量

- 显存预留：乐观 6% / 中性 7% / 保守 8%（可用显存 = 标称 × (1−预留)）
- 激活守卫：×1.10 / 1.12 / 1.15
- 判定：显存需求 ≤ 可用显存 才可行；装不下时优先降微批（不加卡），再降 GA，最后才加卡。

## 7. 并行策略引擎

- **world = TP × PP × DP**；**EP 从 DP 中划分，不再另乘**；本页不做推理侧 Prefill/Decode 分离。
- **TP**：候选 {1,2,4,8}，需整除 Q 头数（GQA 时还需整除 KV 头）；按模型结构给下限（LoRA：hidden≥8192 或 heads≥128 或总量≥400B → 4；全参：≥7168 hidden / ≥128 heads / ≥200B → 8 等）。
- **PP**：候选 {1,2,4,8,16} 且 ≤ 层数/8；全参大模型才触发（≥200B 且 PP 段≥8 → 4；≥100B → 2）。
- **EP**：从 DP 中划分（DP ≥128/64 → 4；≥16 → 2），要求 DP % EP == 0；MoE 时 EP 接近专家数平方根量级打分更优。
- **SP 序列并行**：自动按序列长度开启（>8K → 2 路，>16K → 4，>32K → 8），沿 TP 域切分。
- **自动推荐**：对 TP×PP 组合枚举打分——显存装得下 +1000；装不下按超出量扣分（上限 −240）；副本利用率、PP 气泡（LoRA −28/级、全参 −14/级）、TP 偏离推荐值（每档 −36）、EP/DP 不整除 −40 等；取最高分。
- **手动指定**：TP/PP/EP 可手工输入，引擎校验可行性。

## 9. 关键设计原则（供 ComputePlanner 参考）

1. **算力计费以激活参数量为口径**，MoE 模型总参数只影响显存与专家并行划分。
2. **LoRA 不省算力省显存**：长序列下 FLOPs 仅少 15–35%，但优化器/梯度显存大幅下降。
3. **MoE 通信开销写在分母**：只拉长时间，不夸大总计算量，与预训练同一口径。
4. **显存是硬约束、算力是软约束**：先按算力反推卡数，再用显存下限兜底，最后按并行副本对齐。
5. **装不下优先降批次（微批→GA），不降模型切分**，避免无谓加卡。
6. **双模式互为校验**：模式 A 的卡数 ↔ 模式 B 的耗时，用同一套 FLOPs 与有效算力公式。
7. **三档预设本质是 MFU/重计算/杂项/预留的组合偏移**，而不是改公式。
8. 明确声明**理论估算 ≠ POC 实测**，输出为预算量级，不作为验收依据。
