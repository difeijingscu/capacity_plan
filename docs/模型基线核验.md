# 模型与参考卡基线核验

核验日期：2026-10-20（用户时区）；目录种子为 `backend/app/catalogs/models.json`、`cards.json`。本次仅核验官方元数据和规格，不下载模型，不执行推理/训练，不声称获得任何匹配业务负载的实测吞吐或延迟。

## 1. 数据约定

参数值单位为“参数个数”，不是B；CV工作量为FLOP/帧；卡规格 `dense_p16` 单位为BF16稠密PFLOPS，显存为十进制GB。null表示尚未核验、未适配或不适用，不能替换成0。模型 `evidence_grade=C` 是当前容量估算链路的等级，不代表官方结构事实本身不可信。经验效率、2N简化、训练档位、视觉编码代理和缓存代理不能冒充官方性能。

HF模型的revision固定为公开API返回的完整Git SHA。元数据源为官方发布组织的模型卡、config.json和HF官方API；历史计算需保存目录快照，未来联网更新不改变历史。YOLO26的revision固定Ultralytics源码/文档Git提交，不等于权重文件哈希。计算工具不需要加载权重。

## 3. 缓存和多模态边界

- Qwen3-8B为36层、8个KV头、128头维，适用标准GQA公式。配置max_position_embeddings为40960；超过设计允许的通用长度仍需专门工作负载基线，配置上限不是SLA保证。
- Qwen3.6-35B-A3B为10层全注意力＋30层线性注意力；27B为16＋48。目录 `cache.layers` 特指全注意力层数。线性状态需另外适配，不能将这些模型的全部层数套GQA，也不能只算全注意力缓存就标记完整显存。两者原生配置上下文为262144。
- Qwen3.6的语言激活参数没有覆盖图像编码。整体权重驻留使用完整张量统计；图文计算必须增加图像编码及视觉Token。缺失图像编码基线时保持PARTIAL或由用户接受可见C级代理。
- R1采用MLA，V4采用CSA/HCA，V4.1采用CED、CSA2及压缩缓存。目录 `cache.type=unknown` 表示本工具未提供对应计算适配，并不是声称官方架构未知。没有显式代理时只能给权重下界或显存未知。
- V4.1官方为原生图文模型，其552B主干之外另有196B Engram等组件，不能用552B冒充完整GPU驻留。官方890 byte/token只针对特定全局缓存口径，不是完整部署显存，本目录未直接采用为全显存公式。
- R1/V4官方包使用混合精度，并包含量化元数据或辅助张量；HF safetensors.total不可以不加辨别地作为BF16参数总数。本目录标称主干参数所形成的是C级BF16参考估算，不是发布包物理大小。

以上边界来自各模型固定revision的官方模型卡及config.json；本工具尚无实测校准。`eligible_training_methods`仅列工具可选择的估算方式，不是训练框架兼容性或落地可行性认证；前沿候选无适配时留空。

## 4. CV工作量

YOLO26n/s/m的640×640 COCO检测，分别使用5.5/20.9/68.4 GFLOP每帧。此值是官方融合推理图的工作量，包含卷积/BN融合及未使用检测分支移除；完整训练checkpoint可能有更多参数。只适用此任务和输入形状，不覆盖分割、其他图像尺寸或全部CV任务。官方文档内特定设备的速度没有移植成本工具的可用吞吐。[固定官方文档](https://github.com/ultralytics/ultralytics/blob/1da023f708beb274db82c2c04b034c1859ab3fba/docs/en/models/yolo26.md)、[公开模型规格表](https://docs.ultralytics.com/models/yolo26/)

YOLO为AGPL-3.0/Enterprise双许可入口，Qwen三项为Apache-2.0，DeepSeek三项为MIT。目录仅保存许可元数据，不将“开放权重”等同于无条件商用。
