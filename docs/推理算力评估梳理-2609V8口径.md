## 0. 结论速览

1. 该工具是**四约束取 max + SLA 回验 + 形态判定**的容量规划器，不是简单除法模型。链路为：`A 显存 → B Prefill → C Decode → 混部利用率抬升 → D SLA 加卡 → 对齐/扩容`。
2. explain1.md 的**主链路理解正确**（四维取 max、显存看总参/算力看激活参、Decode 是带宽游戏、PD 四闸门），但有 **6 处事实偏差、12 处缺失**，均在本文第 9 节逐条列出。
3. 三个最容易被漏掉、但对结果影响最大的机制：
   - **KV 带宽效率随序列长度衰减** `ko(seq)`：长序列下 KV 读带宽效率最低掉到 0.70/0.82，直接抬高 TPOT；
   - **敏感度三档**（乐观/中性/保守）同时改 MFU、显存利用率、KV 预留、roofline 重叠惩罚、KV walk，卡数结果差 15%~30%；
   - **混部利用率抬升阈值随并发变化**（1.03/1.05/1.1），不是固定 100%。
4. 落库前必须先裁定 4 个口径红旗（第 11.1 节）。原笔记怀疑的"权重 ÷1024³、KV ÷1e9 混用致 7% 偏差"经复核**不成立**（KV 随后乘 `1e9/1024³` 回 GiB，显存路径统一 GiB），见第 11.1 节更正。

## 1. 整体评估链路

```
输入层：模型结构 / 量化(W,A,C) / 业务场景 / 芯片 / 工程开销 / 敏感度档
   ↓
① 显存约束（A）  权重装载下界 + KV 需求 → 枚举 TP×PP×EP×DP → 取总卡数最小解
② Prefill 约束（B） 吞吐卡数 vs 首 Token 时延卡数 → max，机内上限 8 卡封顶
③ Decode 约束（C） 带宽卡数 vs 吞吐卡数 vs A2A 卡数 → max
   ↓ 物理下界 Bd = max(A,B,C)
④ 混部校验：U_pf + U_dc > 阈值(1.03/1.05/1.1) → 按超出比例抬升下界
⑤ 形态判定：PD 分离（4 闸门 → 4 动机）→ 混部卡数 vs 分池卡数取对应值
⑥ SLA 回验（D）：落 TP×PP×EP×DP → 预测 TTFT/TPOT/并发 → 不达标逐级加 DP
   ↓
输出：推荐卡数（对齐单实例卡数、非单卡方案补偶）/ 扩容余量 / 服务器台数 / 瓶颈标注 / 芯片对照
```

默认加载算例（源码末尾自测入口，可作回归基线）：场景=`长文生成`（1024/8196/32768/9/1000ms/50ms）、模型=`DeepSeek-V4-Flash`（284B/A13B）、芯片=`950(486T)`。

### 2.2 量化三轴（W/A/C 独立）

| 轴 | 取值 | 字节 | 作用 |
|---|---|---|---|
| W 权重 | BF16/FP16 · FP8/INT8 · FP4/INT4 | 2 / 1 / 0.5 | 权重体积、装载下界、Decode 读带宽 |
| A 激活计算 | BF16 · FP8 · INT8 · FP4 | 2 / 1 / 1 / 0.5 | 选算力口径：`int4` 仅 950 原生，910B/C 强制降为 int8 |
| C KV Cache | auto · bf16 · fp8 · int8 | 2 / 1 / 1 | KV 显存与并发容量 |

- `auto` 规则：权重 BF16 → KV BF16；权重 INT8/INT4 → KV FP8。
- W4A8 反量化开销：`nativeInt4 ? 1.04 : 1.06`，乘在 Decode 工程开销上。
- 精度自动推荐 `D()`：`total ≤ 14B` 且 `权重(2B) > 0.85×单卡显存` → 推荐 INT8，否则 BF16；`total > 14B` 一律推荐 INT8。仅提示，不强制。

## 3. 维度 A：显存约束卡数

### 3.1 KV Cache 每 token 字节（源码 `Yn`）

```
L_eff = L × f            f = gqaKvFraction（全注意力层占比，默认 1）
若 swa>0 且 f<1 且 seq>0：L_eff = L × (f + (1−f) × min(1, swa/seq))

MLA：  kvB/tok = L_eff × (latentDim + ropeDim) × C_bytes ÷ 1e9
其他： kvB/tok = 2 × L_eff × kvH × kvHeadDim × C_bytes ÷ 1e9
```
- `kvHeadDim` 留空时等于 `headDim`；`ropeDim` 缺省 64。
- 展示用等效比：`MLA vs MHA = (latentDim+ropeDim) / (2×heads×headDim)`。

### 3.2 KV 显存需求

```
perSessionTokens = mean:  in + out/2
                   p90:   in + 0.9×out
                   full:  maxCtx
（再 clamp 到 [1, maxCtx]）
KV_need = kvB/tok × perSessionTokens × conc × kvReserve
```
- 场景切换会强制回到 `mean`；当 `maxCtx > in+out+4096` 时自动切 `full`。
- Prefix Cache **不缩减 KV**，只折减计算。

### 3.3 权重与激活显存

```
W_GB      = total(B) × W_bytes × 1e9 ÷ 1024³            ← 注意是 GiB 口径
单卡可用   = chipMem × memFill（默认 0.90）
权重下界   = ⌈W_GB / 单卡可用⌉

激活显存：
  batchTok = min(conc × min(in, chunkTok), 单步批 token 上限)
  FFN 项   = batchTok × hid × max(ffnMul×gated, 3) × A_bytes ÷ 1024³
  基线项   = batchTok × hid × 3 × A_bytes ÷ 1024³
  actInst  = max(FFN 项, 基线项) × PP放大系数
```
- PP 放大系数 `ao(PP)`：PP=2 → 1.15，PP=3 → 1.25，PP≥4 → `min(1.5, 1.2+0.05×(PP−4))`。
- 注：注意力激活项 `batchTok × heads × chunkTok × 2` 有计算但未进入 `actInst`（实现遗留，见第 11.2 节）。

### 3.4 实例枚举（源码 `Ro`）

```
for EP in EP候选集：
  for TP in 1,2,4,8（机内上限 8）：
     PP = max(1, ⌈权重下界 / TP⌉)；unit = TP×PP×EP
     预过滤：若 单实例Decode权重读取时间 > TPOT 目标×带宽预算（decodeWeightGB/unit > bw×uWeight×TPOT）→ 跳过该拓扑
     kvCap = unit × 单卡可用 − 单实例权重 − 激活
     若 kvCap ≤ 0.5 跳过
     inst  = ⌈KV_need / kvCap⌉
     total = inst × unit
     score = total × PP惩罚 × EP惩罚
           PP惩罚：PP>2 每级 +6%
           EP惩罚：capacity 模式 +8%×log2(EP) / production 模式 +2%×log2(EP)
取 score 最小解（同分依次比：EP 小 → Dense 取 TP 小/MoE 取 TP 大 → PP 小）
显存卡数 A = max(权重下界, unit, total)
无解兜底：贪心 TP=2^k、EP=1，PP=⌈权重下界/TP⌉，DP=⌈KV_need/kvCap⌉
```

**MoE 权重切分**（`moeWeightPerCardGB`）：先把总参拆成「共享专家 / 路由专家」两部分（按 `active/total` 反解共享比例），再
`共享 ÷ (TP×PP) + 路由 ÷ (TP×PP×EP) × 专家命中率`。
命中率 `hit = min(1, uniform × 1.08)`，`uniform = 1 − (1 − topK/experts)^batch`（偏斜系数 1.08）。

## 4. 维度 B：Prefill 约束卡数

### 4.1 计算量

```
newTok    = round(in × (1 − prefixHit))
prefixTok = in − newTok
FFN 有效token rl  = newTok + 0.10 × prefixTok        ← 前缀残余系数 0.10
平均跨度   span  = min(prefixTok + (newTok+1)/2, attnSpan)

GEMM   Pl = 2 × active(B) × 1e9 × rl ÷ max(0.08, fill)
注意力 wl = (MLA ? 2 : 4) × L_eff × heads × dim_attn × newTok × span
           MLA 时 dim_attn = qkHeadDim + vHeadDim（DeepSeek V3 = 320；GLM5 = 512）
线性层 Fl = L_lin × 2 × newTok × hid × headDim      L_lin = L×(1−f)
总计算量 kl = (Pl + wl + Fl) × fn      fn = cSched × cCM × 反量化（不含路由）
```

**FFN 填充率 `fill`**（小批量下 MoE 专家块填不满）：
```
MoE：s = min(topK, experts−1)；l = newTok × s / experts
     r = 1 − e^(−l / 800)
     fill = clamp(0.07 + 0.43×r) × min(1.15, 1+0.05×log2(实例卡数))，上限 0.70
Dense：fill = 0.42 + 0.58 × (1 − e^(−rl / 5500))
```

### 4.2 单卡有效算力（roofline）

```
权重读 Ll = W_GB × (newTok / 单步批token) × 分块数
KV 读   Bl = kvB/tok × in
裸 OI   Al = kl_裸 / (1e9 × (Ll + Bl))     ← kl_裸 不含工程开销 fn（fn 只乘在需求算力侧）
加权 OI Rl = (Ll + Bl) / (Ll/uWeight + Bl/uKv)     uWeight=1.05×base, uKv=0.82×base
带宽可达 Il = 1e9 × bw(GB/s) × Al × Rl ÷ 1e12
有效算力 ql = min(cf × MFU_pf, Il)                 ← 取 min 即 roofline 拐点判定
```

**Prefill MFU 饱和曲线**：
```
MFU_pf = baseMFU × max(0.45, 0.45 + 0.55×(1−e^(−rl/512))×√min(1, rl/128)) × 0.72
下限 5%
```

### 4.3 两个卡数取 max

```
需求 QPS  nl = conc ÷ E2E_口径(秒)     E2E_口径 = clamp(系统预测E2E, E2E_target/100, E2E_target×100)
          其中 E2E_target = TTFT_t + TPOT_t×(out−1)；预测E2E 由上一轮 SLA 预测回代（自洽迭代）
需求算力   _l = kl × nl ÷ 1e12

吞吐约束  Ol = _l ÷ ql
          长序列折减 Ul = 1 + 0.12×log2(max(1, seq/16384))   （seq>16K 才 >1）
          Gl = ⌈Ol ÷ Ul⌉

时延约束  引擎固定开销 zl = f(层数, 卡数, 输入长, 是否MoE)   ← 见下
          预算 Yl = min((TTFT_t − zl)/1000, cap)   cap = TTFT>15s ? 60s : 10s
          Jl = ⌈kl ÷ (1e12 × ql × Yl)⌉
          nr = min(Jl, 8)        ← 机内 TP 上限，超出即标"TTFT 物理不可行"

B = max(Gl, nr)
```

引擎固定开销 `wo()`：
```
( 260 + (MoE ? 140×clamp(active/13, .75, 1.8) : 70) + (MoE?3:1.8)×L )
  × (0.85 + 0.15×(1−e^(−in/2048))) ÷ cards^0.22
+ (MoE ? 1.2 : 0.45) × L × (in/16384) ÷ cards^0.20
```

## 5. 维度 C：Decode 约束卡数

### 5.1 每步搬运与算力

```
权重搬运 Or = 共享GB + 路由GB × hit            （MoE；Dense 即 W_GB）
KV 每路     Wr = kvB/tok × min(in + out/2, attnSpan)
单步KV搬运  = Wr × 有效批 ÷ KV并行度

带宽时间 = 权重GB ÷ (bw × uWeight) × 1000
         + KV_GB ÷ (bw × uKv_dc × ko(seq)) × 1000    ← Decode 侧 uKv_dc = 0.85×base（Prefill 侧是 0.82×base）
```
**KV 带宽效率衰减 `ko(seq)`（explain1 缺失）**：
```
t = (seq − 4096) / 12288，clamp 到 [0, 1.35]
ko = max(floor, 1 − slope × t)
Dense：slope 0.12，floor 0.82      MoE：slope 0.16，floor 0.70
```
即 128K 序列下 KV 读带宽效率只剩 0.70~0.82，这是长上下文场景卡数下不去的直接原因。

### 5.2 Decode MFU 与 TPOT 合成

```
MFU_dc = MFU_pf × (0.58 | 0.66) × max(0.6, 0.6+0.4×(1−e^(−batch/4))) × 1.25
计算时间 = 注意力FLOPs ÷ (cf × TP × MFU_dc)  +  线性层FLOPs ÷ (cf × TP×EP × MFU_dc)

TPOT = max(带宽时间, 计算时间 × 批拥挤系数, A2A 通信)
     + 0.4 × (三项和 − max)                       ← 重叠惩罚（保守档改 0.08，见 2.6）
     + TP AllReduce + PP 气泡 + 固定开销 + KV walk
批拥挤系数 = 1 + 0.07×log2(有效批量)
PP 气泡   TTFT 侧 +0.8×(PP−1)；TPOT 侧 +(PP−1)/每实例并发 + 0.24×(PP−1)
固定开销   = 1.35 + 0.012×L   （launch 0.6 + 层 0.012L + sample 0.3 + detok 0.25 + sched 0.2）
KV walk   = 0.08 × kvWalkMul × (seq/4096) × (L/60)   ← 仅 MoE 且 active≥15B
A2A       = batch×hid×topK×bytes×2×(EP−1)/EP×moeLayers ÷ (bw_link×0.55) × 1000
跳数时延   = 0.08×(56/link) × moeLayers × log2(EP)
```

### 5.3 三个约束取 max

```
权重地板   weightFloorTimeMs = W_GB ÷ 有效带宽 × 1000（batch=1）
           weightFloor > 1.001×TPOT 目标 → 标"已达本芯片显存带宽理论下限"，加卡无效；
           > 0.9×TPOT 目标时即从 max 中剔除吞吐约束项
带宽约束   rd = 所需实例数 × unit
吞吐约束   目标吞吐 Ip = conc × out ÷ min(需求口径E2E, 目标E2E)
           单实例吞吐 td = min(算力上限, 带宽上限)
           od = ⌈Ip ÷ td⌉ × unit
A2A 约束   Np（专家全互联超预算时按 DP 摊薄）
C = max(rd, od, Np)
```

## 6. SLA 回验：TTFT / TPOT / 并发

### 6.1 TTFT 合成（源码 `evalSlaAtDp`）

```
tRoof = max(tComp, tHbm, tComm) + 0.4×(三者和 − max) + engineMs
Prefill 服务时间 = tRoof + (混部 ? 分块数 × 单步 Decode 时间 : 0)
                   ← 分块预填充只影响混部插入，不改首 Token（首 Token 仍等全量）

排队：ρ = min(0.95, conc × 服务时间 ÷ (服务时间 + Decode 占用时长))
      残余等待 = 0.5 × 服务时间 × ρ
槽位：slotShare = ⌈有效批 ÷ maxNumSeqs⌉，超额时等待 = (slotShare−1) × Decode 步长
混部：Decode 被 Prefill 插入，额外等待 ≈ 0.5 × Decode 步长（分池时为 0）

TTFT = Prefill服务时间 + max(排队残余, 槽位等待) + 混部调度等待
```
- `maxNumSeqs` 自动 = `max(8, min(2048, 单步批token上限))`，默认 256。
- 有效批：主链路 Decode 侧 = `min(conc, conc×填充因子, maxNumSeqs)`（填充因子默认 1，即 min(conc, maxNumSeqs)）；`evalSlaAtDp` 内部 = `min(conc/DP, conc×填充因子)`。KV 显存仍按全部在线会话计。
- 有效生成占比固定 100%（`_t=100%`），即假设所有在线会话同时在出字。
- 槽位：`slotShare = max(1, 有效并发 ÷ maxNumSeqs)`（**无向上取整**），超额时等待 = (slotShare−1) × Decode 步长。

### 6.2 并发上限（四约束取最小，二分搜索）

| 上限 | 口径 |
|---|---|
| 显存 KV | ⌊单实例KV容量 × 并发 ÷ 每路KV需求⌋（反解最大并发） |
| 批槽位 | ⌊并发 × maxNumSeqs ÷ 填充因子⌋ |
| 吞吐 | ⌊单实例吞吐 × 并发 ÷ (1000/TPOT)⌋ |
| 时延 | 二分：使 TTFT ≤ 目标×容差 且 TPOT ≤ 目标×容差 的最大并发 |

达标判据：`SLA_PASS_TOL = 1.00`（严格不超目标）、`SLA_LAT_TOL = 1.10`（容差仅用于"停止加卡"，不算达标）、`CAP_STOP_TOL = 0.95`（并发达需求的 95% 即停）。

## 7. PD 分离判定

**4 个闸门（任一命中 → 不分离，闸门优先于动机）**

| 闸门 | 判据 | 依据 |
|---|---|---|
| 互联 | 单请求 KV 跨池搬运 > TTFT 目标的 30% | 搬运 = `kvB/tok × in ÷ (0.7×互联带宽)` |
| 规模 | 混部下界 < 16 卡 | 池化收益摊不平，业界实测反掉 20~30% |
| 短输出 | out ≤ 64（Dense ≤ 128） | Decode 太短，无逐 Token 稳定性可解 |
| Dense 权重 | Dense 且 in < 32K | 两池各持一份权重摊不平 |

**4 个动机（命中越多越倾向分离，取第一个命中）**

| 动机 | 判据 |
|---|---|
| Prefill 重载 | Prefill 时间片 ≥ 35% 且 TPOT 目标 ≤ 60ms |
| 混部重叠 | Prefill + Decode 利用率之和 > 1.05 |
| 拓扑冲突 | in ≥ 4K 且下界 ≥ 32 卡 且（MoE 或 TTFT 需 TP ≥ 4） |
| 超大规模 | ≥ 128 卡 且 in ≥ 4K |

分离后：P 池按 TTFT 定卡（`max(Gl, nr)` 对齐），D 池吸收显存约束并满足 TPOT（`max(rd, ns)`），跨池 KV 搬运时延计入 TTFT。

## 8. 综合卡数合成

```
物理下界 Bd = max(A, B, C)

混部利用率：U_pf = 需求算力 ÷ (Bd × ql)
           U_dc = max( Decode 需求 ÷ (Bd × 单卡Decode算力), min(1.5, 0.7 × C/Bd) )
                  ← 0.7×C/Bd 项有 1.5 封顶
阈值 thr = conc≥256 ? 1.03 : conc≥16 ? 1.05 : 1.10
若 U_pf + U_dc > thr（**豁免**：单卡可装载的 Dense 小模型，权重下界=1 且 active<30B 且非 split 拓扑，不触发抬升）：
混部下界 = max(A, ⌈max(B,C) × (U_pf+U_dc)⌉)

形态：PD 分离 → 卡数 = max(P池 + D池, A)；混部 → 卡数 = 混部下界
对齐：向上取整到单实例卡数；非单卡方案时总数补偶（奇数 +1）
D 加卡：从下界开始逐级加 DP（每次 1 个实例），绑定项按 TPOT → TTFT → 并发 → 队列 顺序识别；
       停止条件：单路请求即不可达 / 已达单实例 (n+1)×unit 超预算 / 权重地板 / 连续两轮无改善

扩容余量 = ⌈1.2 × 推荐卡数 ÷ 单实例卡数⌉ × 单实例卡数，且 ≥ 推荐 + 单实例
服务器台数 = ⌈推荐卡数 ÷ 8⌉
```
输出另含：瓶颈标注（显存 / Prefill / Decode）、QPS 供需、输入/输出/总吞吐、显存水位、单卡吞吐、三芯对照、风险提示。
供需口径：需求 QPS = `conc ÷ 需求口径E2E`（= clamp(预测E2E, 目标E2E/100, 目标E2E×100)，自洽迭代）；供给 QPS = `达标并发上限 ÷ 需求口径E2E`（**不是**"副本数 × 每副本 TPS"，explain1 此处理解有误）。

## 11. 复用前必须裁定的问题

### 11.1 口径红旗（高优先级）

1. ~~单位不统一~~ **（本次复核更正：原判断不成立）**。权重公式用 `÷1024³`（GiB），KV 公式（`Yn`）确实先 `÷1e9` 得 GB，但源码全局有 `n = 1e9/1024³`，随后 `zo = jo×n`（KV 需求）、`Vi = Gi×n`（Decode 权重）都换算回 GiB。**显存路径统一 GiB，带宽路径统一十进制 GB（与 GB/s 自洽）**，工具界面展示公式也写"÷ 1024³"。主链路中不存在"约 7% 系统性偏差"。移植时真正要守住的是这条分工：**显存容量按 GiB、带宽时间按十进制 GB**，不要交叉混用。
2. **并发是示例值**：37 个场景并发全为 9/6/4，与"按在线会话数估"的说明不符。落地必须由业务量推导（在线人数 × 人均并发率）。
3. **有效生成占比固定 100%**：意味着排队与吞吐按"所有会话同时出字"估，对长输出场景偏保守、对短输出高频场景偏乐观（代码里预留了 `_t` 变量但未开放）。
4. **PD 判定结果有缓存粘滞**：按配置 key 缓存 `mixed/split`，改参数后可能不重算。若移植必须去掉缓存或显式失效。

### 11.2 实现级瑕疵（低优先级，移植时修正）

- 注意力激活显存 `Ki` 计算后未使用，实际用的是 `Ii`（FFN 项与 3×hid 基线项的 max）。
- 分块预填充开启时 TTFT 仍按全量计（设计如此），但混部插入项按"块数 × Decode 步长"线性叠加，长输入下略高估。
- 滑动窗口分支（`swaWindow`）在代码中存在，但 32 个预设均未填该字段，当前实际只走"全注意力层占比"折算路径。
- MTP / 投机解码未建模（`mtpGain` 恒为 1），高吞吐场景会高估卡数 10%~20%。
- 多模态视觉 token 未建模（纯文本口径）。
- 跨机 TP 未支持（机内 8 卡硬上限），超 8 卡即标"TTFT 不可达"。

### 11.3 建议的接入方式

1. **方案 A（照搬）**：把第 2~8 节公式以纯函数实现（语言无关），数据用第 10 节表结构。优点：与参考工具同口径，结论可比；代价：需要把 290KB 脚本的隐含常数全部显式化（本文第 2.5/2.6/10.2 已给出）。
2. **方案 B（分层降级）**：A/B/C 三维保留完整公式，TTFT/TPOT 用简化合成（去掉排队与 KV walk），仅做量级判断。优点：实现量减少约 40%，可解释性强；代价：高并发场景下会低估 10%~20%。
3. **方案 C（包一层）**：把参考工具作为"参考实现"生成基线卡数，自有引擎做增量修正（业务量、TCO、多模态）。优点：快速起步；代价：两套口径长期并存，需明确以谁为准。

建议：**核心规划用 A，对外报价用 B 的简化版做交叉校验，C 仅作为迁移期过渡**。
