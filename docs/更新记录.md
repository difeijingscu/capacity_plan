## 2026-11-16：修「停止后重启报端口被占用」

- **症状**：`.\停止.ps1` 输出「原服务已退出，未停止其他进程。」，紧接着 `.\启动.ps1` 抛「端口8000已被其他程序占用，请使用启动.ps1 -Port 8008」。实测现场：8000 仍被本项目的 `python.exe -m uvicorn app.main:app --app-dir ...\backend`（pid 12164，父进程 4092 是 venv 转发壳）监听，`/api/v1/health` 正常返回 `engine-v2.0.4`，但 `data\server.json` 已被删除——旧的停止脚本在没能杀掉进程的情况下仍然无条件删掉状态文件，下一次启动就彻底失去追踪线索，只剩「端口被占用」。
- **根因**：①判定「是否本项目服务」用 `CommandLine.Contains($PSScriptRoot)`，字符串比较区分大小写、斜杠形式不归一，盘符或目录大小写变化即漏判；②结束进程只按状态文件里的 pid 逐个杀，`launcher_id`（venv 转发壳）被杀后真实解释器可能存活并继续占端口；③端口兜底清理只在 `-not $stopped` 时执行一次，且判定失败后不报告原因，随后删除状态文件。
- **改动（`停止.ps1`）**：以端口监听者为主依据——候选 pid 取「状态文件的 `process_id`/`launcher_id`/`pid`」+「记录端口与 8000 上的实际 listener」；进程判定归一化路径后比较，区分 `ours` / `other-sandbox`（另一个算力沙盘实例）/ `foreign`（其他程序）/ `gone`；命中 `ours` 时按 `ParentProcessId` 递归取整棵进程树后逆序强杀（覆盖壳 → 真实解释器 → 子进程）；杀完轮询端口释放最多 3 秒，仍有残留则输出 pid 与「可手动结束」命令、**保留** `server.json` 并 `exit 1`；确认释放后才删状态文件。`other-sandbox` 只提示不自动结束，避免误杀另一个目录的实例。
- **改动（`启动.ps1`）**：端口上的进程判定为 `ours` 且 `/api/v1/health` 返回 `ok` 时接管现有服务并写回状态文件（状态文件丢失、pid 失效不再误报「被其他程序占用」）；判定为 `other-sandbox` 时提示对方 pid 与命令行；`foreign` 时提示 pid 与进程名；立即启动失败不再依赖 `health` 单独判定（新增进程树清理后再探测端口）。兼容旧版只写 `pid` 的状态文件。
- **验证**（7 个场景，均在本机实测）：正常启动 → 停止 → 端口释放；无服务时停止输出「没有正在运行的本项目服务。」；`server.json` 删除但服务在跑 → 停止按端口杀掉（pid 22876）；状态文件写死失效 pid（999999）但端口有服务 → 仍按端口杀掉（pid 5948）；端口被无关进程（powershell 的 TcpListener）占用 → 报「已被其他程序占用（pid 25560，进程 powershell）」且不误杀；停止两次幂等；连续 stop/start 各两轮 health 均为 `ok`。两脚本保持 UTF-8 with BOM（PowerShell 5.1 中文识别必需）并通过语法解析校验。

## 2026-11-09：算力命名口径拆分为「单位」与「精度基准」（v1.3.2）

原先的 `P16` / `T16` 把两件事压在一个后缀里：`P` / `T` 是**量级单位**（10¹⁵ / 10¹² FLOPS），`16` 是**精度基准**（BF16 稠密）。混写会让人读成「16 位精度下的 P」，也无法表达 FP8 基准。现在拆开：

| 表达对象 | 旧写法 | 新写法 |
|---|---|---|
| 只是算力数值 | `5.00 P16` / `163 T16` | `5.00 P` / `163 T` |
| 说明该处是 BF16 等效 | `P16 等效` | `BF16 基准`（另可写 FP16 / FP8） |

改动范围：

- 前端 `api.ts` 的 `capacity()` 不再拼 `16` 后缀，`0` 显示 `0 T`；`api.test.ts` 断言同步。
- 业务场景页列内标注「BF16 等效」，结果页列标题写「需求算力（BF16）」「建议算力（BF16，含余量）」；规划依据「P16 / T16」条目改为「算力单位 P / T」。
- 后端推导步骤单位由 `P16` 改为 `P`，公式写作 `P = 卡数 × 单卡 BF16 算力(T) ÷ 1000`；`trace.units`、`calculator` 注释与 `business` 文件头口径说明同步。
- 文档（README、开发笔记、设计文档、测试报告、对比报告、部署指南）统一为「单位 P / T + 精度基准 BF16」；历史条目保留原写法并标注。
