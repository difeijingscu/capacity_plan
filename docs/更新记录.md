# 更新记录

## 2026-11-09：算力命名口径拆分为「单位」与「精度基准」（v1.3.2）

原先的 `P16` / `T16` 把两件事压在一个后缀里：`P` / `T` 是**量级单位**（10¹⁵ / 10¹² FLOPS），`16` 是**精度基准**（BF16 稠密）。混写会让人读成「16 位精度下的 P」，也无法表达 FP8 基准。现在拆开：

| 表达对象 | 旧写法 | 新写法 |
|---|---|---|
| 只是算力数值 | `5.00 P16` / `163 T16` | `5.00 P` / `163 T` |
| 说明该处是 BF16 等效 | `P16 等效` | `BF16 基准`（另可写 FP16 / FP8） |

改动范围：

- 前端 `api.ts` 的 `capacity()` 不再拼 `16` 后缀，`0` 显示 `0 T`；`api.test.ts` 断言同步。
- 业务场景页列内标注「BF16 等效」，结果页列标题写「需求算力（BF16）」「建议算力（BF16，含余量）」；规划依据「P16 / T16」条目改为「算力单位 P / T」。
- 后端推导步骤单位由 `P16` 改为 `P`，公式写作 `P = 卡数 × 单卡 BF16 算力(T) ÷ 1000`；`trace.units`、`calculator` 注释与 `business` 文件头口径说明同步。
- 文档（README、开发笔记、设计文档、测试报告、对比报告、部署指南）统一为「单位 P / T + 精度基准 BF16」；历史条目保留原写法并标注。

## 2026-11-06：旧方案打开体验修正（v1.3.1）

验收「打开旧方案」时发现三处会误导人的地方，已修：

- **模型名匹配不上时不再落默认模型硬算**。`business.resolve_spec` 原先在 `MODEL_NOT_MATCHED` 时继续用默认 8B 出卡，等于给出一个换了模型的结果；现在直接报 `MODEL_NOT_MATCHED` 进未计入项，并回带上原模型名，提示重新选择或登记为自定义模型。
- **历史方案里的已下线字段不再阻断打开**。库里旧方案仍带 `planning_start`、`annual_growth`、`development.eval_*` 等字段，而当前 `PlanInput` 是 `extra="forbid"`，导致预览直接 422、页面无数据。新增 `schemas.prune_payload`，在读路径（`GET /plans/{id}`、`GET /projects`、撤销、测算）按当前 schema 递归剪掉未知字段；**写入仍然严格校验**，字段名写错不会被静默吞掉。
- **业务场景页的状态标签与后端一一对应**：`旧字段推导`（能匹配到等价模型）/ `待补模型`（模型为空或不在清单里）/ `不支持`（视频检测、批量任务、原生存量）/ `已估算`。不支持的行把场景类型、精度、服务器、并发置为「不适用」并禁用，表下方直接列出未计入场景与原因，不必先点测算才在结果页发现。
- 表格列重排：需求算力、所需卡数、状态三列固定在右侧，窄窗口横向滚动时结果始终可见。

## 2026-11-02：业务池整体替换为推理链路，过程参数可配置（v1.3）

**业务池不再按「请求速率 × 分阶段 FLOP」算，改为按推理引擎逐场景出卡。**

- 业务场景页重构：每个场景配置「模型（内置清单 + 自定义登记）、推理量化精度（权重 + KV 双轴，默认自动）、业务场景类型、算力服务器、并发会话」，表格直接给出**需求算力（P，BF16 基准）与所需卡数（张）**，池层给出合计卡数与等效算力。
- `Scenario.components` 停用（保留字段以兼容旧数据与导入清单），新增 `Scenario.inference`（`InferenceRequest`）。计算入口 `calculate()` 逐场景调用 `business.resolve_spec` → `inference.estimate`，余量只在池层乘一次。
- 旧方案与 Excel 导入的迁移：无 `inference` 的场景按「模型名去符号模糊匹配 + 任务模板」推导等价配置，打 `MIGRATED_INFERENCE` / `MODEL_NOT_MATCHED` 告警；完全没有模型字段的场景报 `MISSING_MODEL`，不按默认模型硬算；视频检测、批量任务、原生存量报 `UNSUPPORTED_PROFILE` 并计入未计入项。
- 计算推导同步改写：业务池按场景给出「显存约束卡数 → Prefill 约束 → Decode 约束 → 三维取最大（不是相加）→ 时延回验 → 折算参考算力」六步，并注明卡数是物理台数、算力是 BF16 基准的折算值，两者不同量纲。
- 删除旧业务池 UI：场景级技术参数面板（`TechnicalParameterField`）随 `components` 一起下线，`/api/v1/defaults` 仍供创新/研发池使用。

**过程参数全部可配置，便于按反馈迭代。**

- 新增 `backend/app/catalogs/inference_params.json`：11 个规模与迭代上限、12 个卡数聚合与混部、17 个效率与填充率系数、24 个时延常数项，外加芯片效率档（3 档）与敏感度三档（各 9 项）。默认值只在此文件，代码不重复写数字。
- 新增 `backend/app/engine/params.py`：默认值加载、运行时覆盖层合并、按字段区间校验、跨字段一致性校验（MoE 填充率下限 < 上限、混部阈值高 ≤ 中 ≤ 低、并发门限高 > 中、加 DP 停止容差 ≥ 判定容差、分块粒度与批上限、显存利用率 > 50% 等）。越界一律拒绝，不静默截断。
- 改动以「覆盖层」存库（`kind=inference-params`），与默认值分开：升级默认值不会抹掉用户调参，恢复默认随时可回。接口 `GET/PUT /api/v1/inference/params`、`POST /api/v1/inference/params/reset`。
- 新增「基线与设置 → 推理参数」页面：按分组编辑、支持检索、标注「已调 / 未保存」、批量保存生效、一键恢复默认，并展示版本号与口径说明。
- 参数化改造前先抽出全部魔法数字，再用 67 项推理引擎黄金值测试对拍，确认零行为漂移后才接覆盖层。

**验证**：后端 126 项测试通过（新增 MISSING_MODEL、业务池卡数与算力口径、余量只乘一次、1000 场景 < 5 s 等用例）；前端 TypeScript 与生产构建通过；端到端 18 项通过（新增推理参数页 2 项，重写主流程与推导页用例）。删除已下线的 `parameter-defaults.spec.ts`。

## 2026-11-02：新增推理评估（四约束）链路（v1.2）

- 新增「推理评估」页面与 `/api/v1/inference/*` 接口：输入场景使用的模型、推理量化精度、业务场景类型与算力服务器，直接给出该场景所需算力与卡数。
- 与三池规划并存：业务/创新/开发三池仍走原 `calculator.py` 口径，本次未改动；新链路独立服务单场景卡数决策，两条链路互不影响。
- 模型清单内置 32 个（DeepSeek / Qwen / GLM / Kimi / MiniMax 系列），并支持登记自定义模型结构（总参、激活参、层数、注意力维度、专家数与 Top-K）。
- 业务场景档位 6 个：长文生成、知识库问答、深度推理、长文档摘要、超长文档、自定义；切档自动带出输入/输出长度、时延目标与并发示例值，均可改写。
- 算力服务器 6 档：昇腾 910B / 910C / 950(425T) / 950(486T) / 950(547T)·144GB / 950(547T)·96GB。
- 计算链路改为「显存(A) → Prefill(B) → Decode(C) → 混部利用率抬升 → SLA 回验加 DP → 对齐扩容」，**三维取 max 不相加**，不设额外余量。
- 量化按 W/A/C 三轴独立：910B/910C 无原生 INT4 时 A 轴强制降 INT8 并计入 1.06 反量化开销；950 保留 INT4（1.04）。
- 新增敏感度三档（乐观/中性/保守），同输入下结果通常相差 15%~30%，页面与接口都注明所用档位。
- 口径修正：显存路径统一 GiB（÷1024³）、带宽路径统一十进制 GB（÷1e9）；KV 每会话分配量在 maxCtx 明显大于本轮占用时按窗口写满；需求 QPS 用系统预测 E2E 自洽迭代而非固定用目标值。
- 后端新增 `app/engine/inference.py`（纯函数引擎）、`app/catalogs/inference_*.json`（模板数据）、5 个 `/api/v1/inference/*` 端点。原三池计算引擎 `calculator.py` 未改动。
- 验证：后端 123 项测试全部通过（其中推理引擎 67 项，含原工具实测黄金值对拍）；前端 TypeScript 与生产构建通过；推理页 4 项端到端测试通过。
