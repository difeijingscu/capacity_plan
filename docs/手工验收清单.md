# 手工验收清单（v1.3.2 命名口径 / 业务池重构）

- 服务：http://127.0.0.1:8000 （后端托管 dist，单实例）
- 验收对象：项目概览 → 打开「示例 · 组织AI算力规划」
- 参考数据（后端实测，2026-11-09）：企业知识问答 2.47 P / 物理 5 张（含余量 6）；扫描件图文分析 2.53 P / 物理 4 张（含余量 8）；业务池合计 物理 9 张、含余量 14 张
- 参数版本：inference-params-v1（margin_factor 1.2，sensitivity.neutral.mem_fill 0.9）
- 单位规则：`1 T = 10^12 FLOPS`、`1 P = 1000 T`；数字只标量级（`2.47 P`、`559 T`），精度基准写在列标题或小字里，不在数字后缀。

## A 业务场景页（对应验收第 1 项）

- [ ] **A1 列结构** — 操作：进入「业务场景」。预期：9 列依次为 业务场景 / 场景类型 / 模型 / 推理精度 / 算力服务器 / 并发会话 / 需求算力 / 所需卡数 / 状态；横向滚动时右侧三列不移动，首列也不移动。
- [ ] **A2 三行状态** — 预期：企业知识问答「旧字段推导」（橙）、扫描件图文分析「旧字段推导」（橙）、园区目标检测「不支持」（红）。**没有任何一行显示「已估算」**，即没有静默出卡。
- [ ] **A3 场景级数值** — 预期：企业知识问答 需求 `2.47 P`、卡片 `物理 5 张`、`6 张`（含余量）；扫描件 `2.53 P`、`物理 4 张`、`8 张`；园区目标检测 需求/卡数两列均「待补充」。
- [ ] **A4 池合计条** — 预期：`业务池合计 14 张（物理 9 张 · 含 20% 余量 · 需求 6.01 P · 等效 7.84 P）`。*（此条存在口径问题，见 K1）*
- [ ] **A5 未计入项** — 预期：表格下方橙色 Alert「1 个场景未计入合计」，明细一行「园区目标检测：业务池本轮只覆盖大模型推理；视频检测、批量任务与原生存量请改用推理评估页或另行登记」。
- [ ] **A6 不支持行的控件** — 操作：看园区目标检测行。预期：场景类型/模型/精度/服务器均为禁用态、placeholder「不适用」；模型列小字「视频/批量任务 · 业务池不覆盖，选择大模型可改为推理场景」。改为任一大模型后该行恢复可编辑，状态转为「已估算」。

## B 补全与联动（对应验收第 2 项）

- [ ] **B1 只补空字段** — 操作：勾选前两行 → 点「按场景档补全所选」。预期：提示「已按场景档补全 N 个场景的空字段」；并发仍为 100 / 30（不被档位值覆盖）；输入长度、输出长度、最大上下文、首 Token、逐 Token 被填入档位默认值。
- [ ] **B2 幂等** — 操作：再点一次同样的按钮。预期：提示「所选场景的规模参数都已填写，没有需要补的」，数值不变。
- [ ] **B3 并发联动** — 操作：企业知识问答 并发 100 → 300。预期：需求算力与所需卡数都上升（记录改前/改后两值）；**不是等比例翻倍**（推理链路非线性）。
- [ ] **B4 模型/芯片/精度联动** — 操作：① 模型 35B-A3B → DeepSeek-V4-Pro；② 服务器 910C → 910B；③ 权重精度 BF16 → FP8。预期：① 卡数显著上升；② 卡数上升或持平；③ 需求算力下降、卡数通常下降。
- [ ] **B5 无模型拦截** — 操作：新增一个场景（默认已带模型则先清空）→ 点补全。预期：黄色提示「N 个场景还没有选模型，未能补全」，不写入任何字段。

## C 推理评估页（对应验收第 3 项）

- [ ] **C1 默认出卡** — 预期：默认场景直接给出卡数与算力；显存 / Prefill / Decode 三维约束与拓扑（TP/DP/PP）可读；最终卡数等于三维中的最大值，**不是三者相加**。
- [ ] **C2 换模型换芯片** — 操作：大模型 + 弱芯片。预期：卡数增加，时延指标同步恶化。
- [ ] **C3 场景档联动** — 操作：切换业务场景档位（如 知识问答 → 长文档摘要）。预期：输入长度、输出长度、最大上下文随档位刷新。
- [ ] **C4 精度口径** — 操作：权重精度在「自动推荐 / BF16 / FP8」间切换。预期：结果里生效精度随之变化，FP8 的需求算力明显低于 BF16；INT4 在 910B/910C 上按 INT8 计并有说明。
- [ ] **C5 自定义模型** — 操作：登记一个自定义模型 → 在评估页选中。预期：下拉里带「· 自定义」，可正常出卡；刷新后仍在清单里。

## D 自定义模型登记

- [ ] **D1 校验** — 操作：总参留空 / 填 0 / 激活参数 > 总参。预期：阻止提交并给出字段级提示，不产生脏数据。
- [ ] **D2 贯通** — 预期：登记后「业务场景」页模型下拉可选中，标注「· 自定义」，并参与业务池估算。

## E 测算结果页（对应验收第 4 项）

- [ ] **E1 指标卡** — 预期：建议规划总算力卡显示 `6.41 P`（含 20% 余量），副标题含「参考 BF16 稠密等效」；业务池卡显示 `14 张`，副标题「含余量 · 需求算力 6.01 P」。
- [ ] **E2 汇总表列标题** — 预期：需求算力（BF16） / 建议算力（BF16，含余量） / 物理卡数 / 所需卡数（含余量） / 状态；表下小字说明「卡数是物理台数…需求算力以 BF16 稠密算力为基准…两者不是同一量纲」。
- [ ] **E3 单位无后缀** — 操作：全页搜 `P16`、`T16`。预期：0 处命中；所有数值形如 `2.47 P`、`559 T`、`6.01 P`。
- [ ] **E4 未启用/部分计入** — 操作：关闭创新服务池后重新测算。预期：该池卡片显示「本方案未启用」，不显示 0 卡；业务池部分计入时状态为「需复核」并给出未计入条数。

## F 计算推导（对应验收第 5 项）

- [ ] **F1 六步顺序** — 预期：显存约束卡数 → Prefill 约束卡数 → Decode 约束卡数 → 三维取最大（不是相加）→ 时延回验 → 折算参考算力。
- [ ] **F2 公式与单位** — 预期：折算步骤公式为 `P = 卡数 × 单卡 BF16 算力(T) ÷ 1000`，单位标注「P，BF16 基准」；每一步都有真实代入数字，不是占位符。
- [ ] **F3 历史口径** — 操作：改一个输入但不重新测算，再打开推导。预期：展示的是上次测算的输入；提示「输入已变更，结果为历史快照」；重新测算后更新为新输入。
- [ ] **F4 异常与窄屏** — 操作：关闭某资源池 / 制造缺失任务；缩到 390px 宽。预期：缺失项与未启用池有明确说明；抽屉内可阅读、无横向溢出。

## G 推理参数（对应验收第 6 项）

- [ ] **G1 页面结构** — 路径：基线与设置 → 推理参数。预期：标题带 `版本 inference-params-v1`；6 个 Tab：规模与迭代上限 / 卡数聚合与混部 / 效率与填充率系数 / 时延常数项 / 芯片效率档 / 敏感度三档。
- [ ] **G2 保存生效** — 操作：卡数聚合与混部 → 扩容余量倍数 1.2 → 1.5 → 保存并生效。预期：按钮显示「保存并生效（1）」；保存后 Tag「已调 1 组」，字段旁出现「已调」；刷新页面仍在；业务池卡数按比例上升。
- [ ] **G3 越界拒绝** — 操作：把某字段改到超上限（如余量 3.5）。预期：输入框限制或保存返回 422 并提示具体字段，不写入。
- [ ] **G4 敏感度三档** — 操作：敏感度三档 → neutral（中性）→ 显存利用率 0.9 → 0.6 → 保存。预期：同一场景卡数上升（可用显存变少）；乐观/保守两档数值独立，不串档。
- [ ] **G5 恢复默认** — 操作：点「恢复默认」。预期：覆盖层清空、Tag 消失、各字段回落默认值；卡数回到基线（企业问答 5 张 / 扫描件 4 张）。
- [ ] **G6 生效范围** — 预期：改参数只影响之后的测算；已保存的历史测算保持原样，结果页出现「输入已变更，结果为历史快照」。

## H 回归

- [ ] **H1 自动保存** — 操作：改场景字段 → 刷新页面。预期：改动保留，未提示错误。
- [ ] **H2 撤销与重算** — 操作：测算 → 撤销改动 → 重新测算。预期：不报 422；卡数与需求算力随修订单调变化，不出现跳变或回退到旧模型。
- [ ] **H3 窄屏** — 390px 宽打开业务场景、结果页、推理评估。预期：页面无横向溢出（表格内部滚动不算）。
- [ ] **H4 旧方案兼容** — 操作：打开 test 方案（含已下线字段）。预期：正常打开不报 422，已下线字段被静默剪枝，界面无空白项。
